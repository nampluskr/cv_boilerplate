### 처리 근거 및 수정 내용

1. **Major #1**: `cli/commands.py::train()`과 `bench/runner.py::execute_split()`에서 `trainer.fit()`
   직후 `checkpoint_dir` 없는 1회용 `Trainer`로 valid를 재평가해 그 결과를 `metrics_final.json`에
   기록하도록 변경했다(`metrics_epoch.csv`에는 추가 행 없음). 수정 후 4개 벤치마크 재실행 결과
   EfficientAD의 valid `image_auroc`가 `0.805`(calibration 이전) → `0.610`(calibration 이후,
   test와 같은 모델 상태)로 정정됨을 확인했다. toy 4종은 `on_fit_end`가 no-op인 3종에서 재평가 값이
   기존 `best_metric`과 정확히 일치, `toy_anomaly`에서는 `pixel_auroc`가 `0.99909...`→`0.99895...`로
   미세하게 달라져 계산 경로가 실제로 재평가를 타고 있음을 확인했다.
2. **Major #2**: `core/builders.py::build_optimizer()`가 `p.requires_grad`로 파라미터를 필터링하도록
   수정했다. 학습 대상 파라미터 집합은 불변이므로(필터링 전에도 teacher 파라미터의 grad는 항상
   `None`이었음) 계약 변경 없음 — 수정 후 4개 벤치마크의 지표가 불변임을 재실행으로 확인했고,
   EfficientAD의 `metrics_final.json`에 기록되는 `profile.params_trainable`(4,847,360)이
   `params_total`(7,541,504)보다 작아져 teacher 제외가 profiling 단계에도 정확히 반영됨을 확인했다.
3. **Major #3**: `core/offline.py`에 `guarded_sendto`/`guarded_sendmsg`를 추가해 `AF_UNIX`가 아니고
   목적지가 loopback이 아니면 `OfflineViolationError`를 던지도록 확장했다. 역검증
   (`sock.sendto(b'x', ('8.8.8.8', 53))`)으로 차단을 재확인했다.
4. **Major #4**: 현재 유일한 사용처인 `configs/benchmarks/detection_baseline.yaml`은
   `control.extra_fields`에 `score_thresh`/`nms_iou`/`max_det`를 이미 올바르게 선언하고 있어(코드
   확인) 실제 위반은 없다. `model.params`를 기본 통제 필드로 승격하는 방안은 서로 다른 모델의
   정당한 `params` 차이(예: `weights_path` 유무)를 전부 예외 등록 대상으로 만들어 채택하지 않았다.
   opt-in 구조 자체의 한계로 `LIMITS.md` §9에 기록하고 리스크로 수용한다.

수정 1~3은 모두 공통 코드(`src/core`, `src/bench`) 변경이므로 `PLAN.md` 5.4에 따라 toy 4종
(bit-exact 재검증 포함)과 4개 벤치마크 전체를 재실행했다 — 12/12 split `status=ok`,
`scripts/check_engine_purity.py` PASSED, `scripts/check_reproducibility.py`로 4태스크
재현성 재검증(anomaly는 이번 수정의 영향을 직접 받는 `efficientad`로 재확인 모델을 교체, 나머지
