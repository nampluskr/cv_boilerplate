## 처리 근거 및 수정 내용

1. **Critical**: `fasterrcnn_resnet50_fpn(...)` 생성 시 `min_size=image_size[0]`, `max_size=max(image_size)`(고정 512×512), `image_mean=[0,0,0]`, `image_std=[1,1,1]`을 명시 전달해 내부 transform의 resize를 no-op으로, normalize를 항등 연산으로 만들었다. `box_score_thresh`/`box_nms_thresh`/`box_detections_per_img`, `strict=True` 로딩 순서는 변경 없음.
2. **Major(YOLO device)**: `forward()`의 빈 검출 분기는 `device=img.device`로 텐서를 생성하고, 일반 분기는 `.cpu()` 호출을 제거해 `.detach()`/`.clone()`만 수행하도록 수정. 세 모델 모두 입력 device를 유지하는 동일한 규약으로 통일.
3. **Major(class_names)**: `TaskAdapter`에 `bind_class_names_from_config(data_config)` 훅(기본 no-op, Grade B)을 추가하고 `DetectionAdapter`가 override해 `data.params.class_names`로부터 `["background"] + class_names`를 구성하도록 했다. `src/cli/commands.py::predict()`가 어댑터 생성 직후 이 훅을 호출하도록 배선. `train`/`evaluate`는 기존 `bind_class_names(adapter, dataset)` 흐름을 그대로 유지.
4. **Minor**: 각주 문구를 "for tasks whose forward() applies postprocessing internally, that cost is included"로 정정.

수정 후 부수적으로 `scripts/check_engine_purity.py`가 `src/core/adapter.py`/`src/bench/control.py`/`src/bench/leaderboard.py`의 설명용 주석에 남아 있던 `classification`/`segmentation`/`detection` 문자열(실제 분기 로직 아님)을 검출해 실패했다. 계약·동작 변경 없이 문구만 재작성했고, 재실행 결과 PASSED로 확인했다 (`PLAN-P1 §16` 기록).

## 1차 검토에서 함께 확인된 항목 (Codex 보고, 문제 없음)

- N=0/N=1/N>1 혼합 배치: Dataset·transform·collate·Custom FCOS assigner·loss·YOLO 변환 모두 명시적으로 빈 `(0,4)`/`(0,)` 텐서를 처리. oxford_pets의 N=1 전제가 파이프라인에 침투한 흔적 없음.
- target 규약: Dataset/transform 경계는 절대 xyxy, float boxes, 1-based labels 유지. YOLO의 normalized cxcywh·0-based 변환은 wrapper 내부에 격리.
- 이중 NMS: 발견되지 않음. 각 모델 wrapper에서 1회만 수행, adapter가 재적용하지 않음.
- 후처리 통제값(`score_thresh=0.05`, `nms_iou=0.5`, `max_det=100`): 세 모델 동일.
- split 무결성: 생성기가 `assert_disjoint()`를 적용하고, 정본 split 미사용 사유가 `note` 필드에 기록됨.
- 오프라인: YOLO wrapper에서 고수준 `YOLO()`/Trainer, `torch.hub`, 다운로드 호출, offline guard 해제 없음.
- metric reset: `DetectionAdapter.reset_metrics()`가 모든 metric의 `reset()` 호출.
- 엔진 순수성: 지정 공통 파일에서 `"detection"`은 import/주석에만 존재하고 태스크 이름 조건 분기 없음 (단, 주석 자체가 purity 스캔에 걸려 이후 재작성함, 위 참조).

처리량, 1-stage(YOLOv8n)가 정확도-속도 절충, 1-stage from-scratch(custom_fcos)는 파이프라인 검증 목적대로
낮은 정확도·최고 처리량.
