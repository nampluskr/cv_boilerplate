## 처리 근거 및 수정 내용

1. **Major #1 (F1 tie 처리)**: `src/tasks/anomaly/postprocess.py::best_f1_threshold`에 "동일 정렬 점수 구간의 마지막 위치만 유효한 threshold 후보"라는 마스크를 추가했다(`is_last_in_run`, 그 외 위치의 F1을 `-inf`로 마스킹 후 argmax). Codex가 제시한 재현 케이스로 수정을 확인했고, `n=3..7` 전수 브루트포스 비교(별도 스크립트)로도 불일치 0건을 확인했다. `image_threshold`/`pixel_threshold` 양쪽 모두에 영향을 주는 공통 함수이므로 두 threshold 모두 개선된다.
2. **Major #2 (신규 checkpoint_dir + resume 조합)**: 이 결함은 이번 Phase에서 도입한 회귀가 아니다 — `on_fit_end`가 항상 "현재(마지막 epoch) 모델"을 관찰하고 best-reload는 `best.pth` 파일 존재 여부에만 의존하는 구조는 이번 순서 변경 이전(구 코드에서는 reload가 `on_fit_end` *이후*에 조건부로 실행) 에도 동일하게 존재했다 — 구 코드에서도 새 `checkpoint_dir`에 `best.pth`가 없으면 reload가 스킵되어 최종적으로 반환되는 모델이 non-best였다. 이번 변경은 이 edge case를 새로 만들지 않았고, 오히려 `best.pth`가 존재하는 통상 경로(신규 학습, 같은 디렉터리로의 resume)에서는 calibration이 올바른 best-epoch 모델을 대상으로 계산되도록 개선했다. "새 디렉터리로 resume"은 v0.1 CLI 사용 패턴에 없는 드문 조합이며 수정 범위가 `Trainer.fit()`의 resume 분기 전반을 다시 설계해야 하는 규모라 별도 Grade B 변경 요청으로 남기고, `docs/dev/v0.1/plans/PLAN-P1-foundation.md` §16과 P6 `LIMITS.md`에 한계로 기록한다.
3. **Minor (transform 해상도 미강제)**: 설계상 `data.image_size`는 config 스키마가 `[256,256]`으로 고정하고 `validate_config()`가 그 값을 강제하는 계층이며, task transform 함수는 `PLAN-P1 §6.1`의 공통 규약대로 config가 넘긴 `image_size`를 그대로 받는 다른 모든 task transform(`classification_default`, `segmentation_default` 등)과 동일한 패턴이다. task transform 함수 자체에 값 강제를 추가하는 것은 이 프로젝트의 계층 분리 원칙과 어긋나 리스크로 수용한다.

Critical 지적이 없어 `CLAUDE.md` Phase Execution Workflow 3단계("Critical을 수정했다면... 재검토")의
재검토 의무는 발생하지 않는다. Major #1 수정 후 검증 회차는 1/3을 유지한다.

## 확인된 비위반 사항 (Codex 보고)

- `on_fit_start`/`on_fit_end`에 전달되는 loader는 `train`/`valid`뿐이며 test loader는 없음.
- threshold와 EfficientAD quantile 계산은 valid loader만 사용.
- STFPM/EfficientAD teacher는 `requires_grad=False`이고 외부 `train()` 호출 후에도 `eval()` 유지.
- teacher checkpoint는 `load_local_weights()`를 무조건 호출하며 random fallback·anomalib 런타임
  import 없음.
- train target은 `{}`이고 정상 valid/test 이미지에는 zero mask 생성, mask는 `{0,1}`로 변환됨.
- 정상 이미지도 pixel-AUROC에 포함됨.
- 세 모델 모두 입력 해상도의 anomaly map을 반환하며 shared adapter smoothing 사용.
- Engine 변경에 task-name 분기 없음. `on_fit_end`가 no-op인 기존 task의 정상 비-resume 실행에서
  optimizer/scheduler/RNG checkpoint state 불변.
- `TaskAdapter.extra_final_metrics()`는 generic empty-dict 기본 구현.
